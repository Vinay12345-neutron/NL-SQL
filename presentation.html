The 4-Stage Execution Pipeline

Stage 0

Dense Retrieval

Qwen3-Embedding-8B cosine similarity → Top-20 candidates

→
Stage 1

Plausibility Filter

Gemini 2.0 Flash narrows to ≤5 truly plausible DBs

→
Stage 2

SQL Broadcast

DeepSeek V3.1 generates SQL async for each candidate

→
Stage 3

SQLite Execute

Local execution: POPULATED / VALID_STRUCTURE / EMPTY_SET / ERROR

→
Stage 4

Judge

Gemini LLM judge selects best DB from execution evidence

Async SQL generation (semaphore=5) Infinite retry with exponential backoff Incremental JSONL saving + auto-resume Threading timer kill-switch (Cartesian joins)
Key Innovation

Spider-Specific: Structural Coherence Routing

🐦

BIRD (Data-Presence)

BIRD databases are fully populated. The judge uses POPULATED vs EMPTY_SET as the primary signal — the DB returning real rows wins.

POPULATED = strong positive signal
🕷️

Spider (Structural Coherence)

Spider is mixed — some DBs are empty, some (like academic) have real data. Execution results alone are misleading.

VALID_STRUCTURE = primary signal
🔍

Judge Rewrite

Spider judge prioritises schema specificity — a dedicated keyword table beats a populated generic table using LIKE '%keyword%'.

Schema noun → SQL column alignment

Error Analysis

BIRD Failure Taxonomy (2,286 → 904 failures)

~22%

Cat 1: Retrieval Funnel Drop

Gold DB not in Top-20 — dense retriever failed entirely. Unrecoverable by re-ranking.

~18%

Cat 2: SQL Generator Choke

DeepSeek hallucinated columns or used wrong syntax for the gold DB → classified as ERROR and eliminated.

~35%

Cat 3: "Empty Set" Trap

Valid SQL on gold DB returned 0 rows (logic too restrictive). Judge penalised gold DB despite correct schema.

~25%

Cat 4: Populated Ambiguity

Gold DB returned data, but a different DB also returned data. Judge picked the wrong populated database.

Error Analysis

Spider Failure Taxonomy (1,843 → 979 failures)

~15%

Cat 1: Retrieval Funnel Drop

Gold DB absent from Top-20. Very low rate given Spider R@20 = 97.24%.

~12%

Cat 2: SQL Generator Choke

DeepSeek generated broken SQL for the gold DB → eliminated by Stage 4 judge.

~48%

Cat 3: Unresolvable Ambiguity

Both gold DB and selected DB had VALID_STRUCTURE. All schemas were empty — judge was forced to guess.

~25%

Cat 4: Populated Trap

A populated DB (academic cluster) lured the judge away from the correct but empty gold DB.

Summary

Key Takeaways

  • Execution Evidence is Powerful

    Using SQLite execution to classify POPULATED / VALID_STRUCTURE / ERROR provides strong disambiguation signals that pure schema matching misses.

  • Dataset-Aware Routing is Critical

    BIRD and Spider require fundamentally different judgment strategies due to their different database population patterns.

  • +25.1% BIRD · +16.9% Spider

    Absolute R@1 gains over dense retrieval baseline on the same 5,501 / 5,116 test queries used by Sai et al.

  • SOTA Beaten on Both Benchmarks

    83.57% BIRD (+3.95%) and 80.88% Spider (+1.24%) over Sai et al.'s Modular Reasoning method.
